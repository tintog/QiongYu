# 穹宇气象大模型演示系统——后续开发规划

## 1. 项目目标

在大部分沿用原 AIC 短时强降水系统前端界面和深蓝色气象大屏风格的基础上，建设一套能够参加竞赛演示的最低完整版本。

系统必须跑通以下业务主线：

```text
选择或上传气象数据
        ↓
查看全国或区域降水态势
        ↓
提交模型预测任务
        ↓
展示未来降水预测结果
        ↓
计算强降水风险等级
        ↓
生成风险预警
        ↓
保存预测与预警记录
        ↓
查询历史任务和结果
```

## 2. 开发原则

1. 大部分沿用原 AIC 系统的页面结构、配色、导航栏、地图和图表风格。
2. 不把现有系统重新设计成完全不同的前端。
3. 先完成预测、预警、数据库和历史记录的业务闭环，再完善辅助功能。
4. 雷达可视化作为辅助模块，不作为第一优先级。
5. 没有训练权重时，不将随机模型结果宣传为真实气象预报。
6. 所有演示数据必须标注“演示数据”，真实数据必须说明来源与时间。
7. 大型气象文件保存在本地目录，数据库只保存文件信息、任务记录和结果摘要。

## 3. 最低竞赛版功能范围

### 3.1 必须完成

- AIC 风格的综合态势首页。
- 正确、完整的中国地图。
- 全国或区域降水分布展示。
- 省份、城市或区域选择。
- 气象数据文件管理。
- 模型预测任务提交。
- 输入序列和预测序列展示。
- 强降水风险等级计算。
- 风险预警卡片和地图标注。
- SQLite 数据库。
- 历史预测和历史预警查询。
- 离线演示数据和一键启动说明。

### 3.2 建议完成

- 简化版雷达图展示。
- 雷达文件上传和解析。
- 预测结果逐帧播放。
- 风险区域排行。
- 预测结果导出或截图。
- 数据来源、模型状态和系统状态展示。

### 3.3 暂不建设

- 用户注册和复杂权限系统。
- 多部雷达拼图和融合。
- 水凝物分类等专业雷达产品。
- 分布式计算和消息队列。
- 复杂微服务架构。
- 把 NetCDF、NPY、雷达基数据直接存入数据库。
- 在线训练大型深度学习模型。

## 4. 页面规划

### 4.1 综合态势首页

沿用原 AIC 首页的大屏布局。

中间区域：

- 标准中国地图。
- 降水网格、站点或区域风险着色。
- 支持点击省份或城市查看详情。
- 显示数据时间、数据来源和演示状态。

顶部指标：

- 最大降水。
- 平均降水。
- 有雨网格数。
- 强降水网格数。
- 当前预警数。

左侧面板：

- 降水等级分布。
- 强降水区域统计。
- 数据文件状态。
- 风险等级说明。

右侧面板：

- 未来降水趋势。
- 高风险区域排行。
- 当前预警列表。
- 选中区域详情。

### 4.2 模型预测页面

- 选择模型。
- 选择演示数据或上传 `.npy` 文件。
- 选择输入、输出长度。
- 显示模型是否已加载训练权重。
- 提交预测任务。
- 展示输入帧和预测帧。
- 支持逐帧切换和自动播放。
- 显示运行状态、耗时和错误原因。
- 保存任务和结果。

### 4.3 风险预警页面

- 展示预警区域、等级和时间。
- 展示预测降水值和判定阈值。
- 展示预警依据和建议措施。
- 支持按区域、等级、时间筛选。
- 支持查看对应预测任务。
- 地图使用黄、橙、红等颜色区分风险。

具体阈值必须以任务文档或确认后的业务标准为准，开发过程中不得随意编造。

### 4.4 历史记录页面

- 历史数据文件。
- 历史预测任务。
- 历史预测结果。
- 历史风险预警。
- 按日期、区域、状态和风险等级筛选。
- 查看任务详情。
- 使用历史数据重新运行预测。

### 4.5 雷达监测页面（辅助模块）

最低实现内容：

- 内置一组雷达演示图。
- 显示观测时间、产品名称和数据来源。
- 标出强回波中心和可能影响区域。
- 提供通俗的雷达图解释。
- 条件允许时保留原 AIC 的雷达文件上传和 PPI 绘图功能。

暂不开发复杂仰角分析、雷达融合、回波顶高和水凝物分类等功能。

## 5. 后端规划

继续采用 FastAPI，接口按业务重新整理：

```text
/api/health          系统运行状态
/api/dashboard       首页统计和地图数据
/api/data            文件上传、查询和管理
/api/prediction      预测任务创建、运行和查询
/api/warning         风险计算和预警查询
/api/radar           雷达上传、解析和绘图
/api/weather         实时天气辅助信息
```

后端需要完成：

- 统一接口响应格式。
- 文件类型、大小和内容校验。
- SQLite 数据库连接和初始化。
- 任务状态管理。
- 模型状态检查。
- 预测结果保存。
- 风险等级计算。
- 异常记录和用户可理解的错误提示。
- 去除硬编码密钥、测试输出和无效代码。

## 6. 数据库规划

最低版本使用 SQLite，建立以下数据表：

| 数据表 | 作用 |
| --- | --- |
| `data_files` | 保存上传文件的名称、类型、路径、大小、时间和解析状态 |
| `models` | 保存模型名称、版本、权重路径和可用状态 |
| `prediction_tasks` | 保存预测参数、任务状态、运行时间和错误信息 |
| `prediction_results` | 保存最大降水、平均降水、结果路径和摘要 |
| `risk_warnings` | 保存区域、等级、阈值、预测值、预警时间和建议 |

本地文件目录规划：

```text
storage/
├── uploads/          用户上传文件
├── datasets/         演示和测试数据
├── radar/            雷达文件和图像
├── predictions/      预测结果
├── models/           模型权重
└── exports/          导出文件
```

## 7. 模型与演示数据策略

系统采用双通道方案。

### 7.1 演示预测通道

- 内置可重复运行的降水案例。
- 提供输入序列和对应预测结果。
- 提供至少一个会触发强降水预警的案例。
- 无网络、无 GPU 时仍可完整演示。
- 页面明确标注“演示预测”。

### 7.2 真实模型通道

- 保留并整理 SimVP 推理接口。
- 检查输入形状、归一化方式和输出含义。
- 找到可靠权重后加载真实模型。
- 模型未加载权重时显示“未就绪”，不能冒充真实预测。
- 保存模型名称、版本、权重和预测任务之间的关系。

## 8. 分阶段开发任务

### 阶段一：代码基线与AIC界面恢复

任务：

- 备份现有项目。
- 确认前后端启动方式。
- 对比当前界面和原 AIC 界面。
- 恢复原 AIC 的导航栏、大屏布局、配色和主要组件。
- 使用标准中国地图数据。
- 删除或替换空气质量等无关模块。

完成标准：

- 前后端可以启动。
- 首页视觉上明显继承原 AIC 系统。
- 中国地图显示正确。
- 页面不存在明显错位和遮挡。

### 阶段二：数据库与文件管理

任务：

- 接入 SQLite。
- 建立五张基础表。
- 编写数据库自动初始化逻辑。
- 建立 `storage` 文件目录。
- 完成文件上传、查询和状态接口。
- 使用数据库记录替代临时内存字典。

完成标准：

- 上传文件可以被记录。
- 后端重启后记录仍然存在。
- 前端可以查看文件列表和解析状态。

### 阶段三：预测业务闭环

任务：

- 整理 SimVP 模型接口。
- 增加模型权重状态检查。
- 准备演示输入和预测结果。
- 创建预测任务接口。
- 保存任务状态、参数、耗时和结果。
- 完成预测序列前端展示。

完成标准：

- 用户可以提交一次预测。
- 页面可以显示输入和预测序列。
- 预测记录可以在历史页面重新打开。
- 模型真实状态显示准确。

### 阶段四：风险预警闭环

任务：

- 根据任务标准确定降水风险阈值。
- 开发风险计算服务。
- 自动生成预警记录。
- 完成预警卡片、地图着色和区域排行。
- 展示预警依据和建议措施。

完成标准：

- 强降水演示案例可以自动触发预警。
- 预警能够追溯到数据文件和预测任务。
- 风险等级、颜色和文字说明一致。

### 阶段五：真实GFS数据接入

> 该阶段已完成技术验证。根据当前“优先完成演示系统”的范围，GFS前端入口已隐藏，后台适配代码保留备用，不再作为后续开发主线。

任务：

- 借鉴AIMB的GFS下载与缓存思路，但保留现有FastAPI架构。
- 自动选择已经完整发布到360小时的最新GFS周期。
- 下载中国区域0.25°逐6小时降水并严格筛选6小时累计字段。
- 转换为61时次标准NetCDF并登记SQLite。
- 后台展示任务进度、错误原因，并在完成后自动激活。
- 明确标注GFS为数值预报基线，不冒充AI预测。

完成标准：

- 可以从网页启动一次完整GFS接入任务。
- 生成文件通过61时次、6小时间隔和全国范围校验。
- 首页地图、时间轴和单点曲线读取真实GFS数据。
- 数据来源、起报时间和基线身份显示准确。

### 阶段六：演示数据与AIC式页面切换

任务：

- 默认数据源切换为统一命名的“演示数据”。
- 从数据管理页隐藏GFS下载入口。
- 顶部导航改为主页、模型预测、风险预警、数据管理四个独立页面。
- 点击导航按钮直接替换主内容区，不再滚动到页面下方。
- 模型预测扩展为60个逐6小时时次，覆盖未来15天。
- 保留预测任务、结果和风险提示的数据库追溯能力。

完成标准：

- 无网络环境能够完成核心演示。
- 四个导航页面可以直接切换且保持状态。
- 模型预测能够生成到+360h的60个时次。
- 主页面仅显示“演示数据”，不出现GFS主线或“演示案例”措辞。

## 9. 开发优先级

严格按照以下顺序实施：

1. 恢复并稳定 AIC 前端界面。
2. 修正中国地图和降水展示。
3. 建设 SQLite 和文件管理。
4. 跑通预测任务及历史记录。
5. 建设风险判断和预警功能。
6. 完善简化雷达可视化。
7. 完成测试、文档和竞赛演示包装。

如果时间不足，优先保证前五项完成。雷达专业功能不得影响核心业务闭环的交付。
