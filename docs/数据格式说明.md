# 数据格式说明

## 时间规则

- 起报时刻记为 `+0h`；
- 最远预报时效为 `+360h`；
- 时间间隔为 6 小时；
- 包含起报时刻时，共有 61 个时间点和 60 个预测间隔。

## 地图数据

地图接口返回经度、纬度和降水量：

```json
{
  "lon": 113.0,
  "lat": 23.0,
  "value": 12.5
}
```

`6h` 数据单位为 `mm/6h`，`24h` 数据单位为 `mm/24h`，过程累计数据单位为 `mm`。

## 单点数据

单点接口返回最近网格点、逐 6 小时时间序列、逐日累计值和汇总信息。接入真实数据时必须保持字段名称不变，避免重写前端。

## 数据真实性标识

系统必须通过 `/api/system/info` 返回 `dataMode` 和 `dataNotice`。模拟或演示数据不得标注为真实预报。

## NetCDF预测文件要求

- 时间坐标支持 `forecast_time`、`valid_time` 或 `time`；
- 经纬度支持 `latitude/longitude` 或 `lat/lon`；
- 降水变量支持 `precipitation`、`tp`、`precip`、`rain` 或 `pr`；
- 至少包含从 `+0h` 到 `+360h` 的61个时间点，相邻时间必须为6小时；
- 空间范围必须覆盖约 `73—135°E、16—54°N`；
- 推荐单位为 `mm/6h`，单位为米时后端会换算为毫米；
- 缺失值、无穷值和负降水在展示前归零；
- 文件上传后先校验，只有校验通过后才能激活。

现有AIMB目录中的ERA5 `tp`文件时间间隔约744小时，范围为 `116—122°E、27—36°N`，属于历史华东区域资料，只能作为真实数据解析样例，不能作为未来15天全国预报。
