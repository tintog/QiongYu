# 竞赛版：全国气象与陆家嘴立体城区

## 已实现

- 全国气象继续读取项目现有 NetCDF 产品，不新增或伪造天气数据。
- 地形默认开启；全国时间轴、要素切换、省级定位、单点和风险分析保持原有业务口径。
- 区域定位页新增“上海陆家嘴”：本地16个3D Tiles分块，1,131个建筑/部件，最高632m。
- 建筑近景使用本地道路、水域示意底图及程序化窗格；是简化三维建筑，不是倾斜摄影实景。
- 固定白天光照仅用于场景展示，气象有效时间独立；倾斜/俯视、城区格点曲线、返回全国可切换。
- 城区打开后收起左栏，隐藏省级标注与边界；返回全国恢复气象图层。建筑在相机高于60km时隐藏。
- “离线稳定演示”关闭在线影像与地形，使用本地建筑、道路图和基础底图；全国天气依然需要本地后端服务与数据。

## 演示步骤

1. 按原启动说明启动后端和前端，登录后进入3D大屏。
2. 全国视角播放时间轴，展示气象分布；可切换要素和查询省级中心。
3. 工具栏“区域定位” → “进入立体城区”，展示陆家嘴高层建筑群。
4. 切换“俯视 / 倾斜视角”；点击“查看城区预报”，展示附近原始格点的预报曲线。
5. “返回全国气象”或“复位”，恢复全国气象总览。
6. 比赛网络不稳定时选择“离线稳定演示”。也可在原系统URL增加 `?sceneOffline=1` 后进入3D大屏，初始化即关闭远程地图并自动打开本地城区。页面仍正常登录，不绕过权限。

在线模式地形默认开启。离线模式明确关闭远程地形，用椭球面展示；图层页可重新开启地形和切换在线影像。

## 数据和边界

建筑资源及来源数据共约6MB，随 frontend/public/buildings/lujiazui 提供，构建后自动复制到 dist/buildings/lujiazui。保留该目录内README及ODbL署名。当前只有这一个城区有建筑覆盖，不宣称全国建筑已经接入。

高度来源和几何局限详见模型目录README与manifest。近景天气仍为原始预报格点，不能解释成逐栋楼宇气象预报。高清卫星影像与真实地形仍需网络；离线道路图是示意制图。模型没有真实建筑立面照片。

## 验证

- 真实本地2026092800批次：60个时效，+24h全国场采样12,549点；最大6小时降水42.33mm。
- 后端6项气象回归通过：单位转换、地图与单点一致性、累计、风险、缺实况处理、监测版本。
- 资源状态与气象栅格方向/透明度单元检查通过。
- 浏览器验证脚本 frontend/tests/competition-city-browser.cjs 使用由真实服务导出的响应，独立挂载大屏组件；不使用登录凭据，也不代替全系统登录链路测试。
- 浏览器结果：16个本地模型分块全部加载；1366×768和1920×1080无面板/工具重叠；全国下一时效、城区曲线、俯视/倾斜、返回全国和关闭远程资源后的离线启动均通过，无页面脚本错误。
- 重现浏览器验证：先运行 backend/.venv/Scripts/python.exe tools/export_weather_validation.py，再从frontend目录执行测试脚本，配置本机Playwright模块路径。

生产构建：从frontend运行 npm run build。部署保留 /cesium 与 /buildings 静态目录，并按原说明配置 /api 和 /scene-assets 转发。

## 2026-10-10 建筑与底图衔接修复

城区模型与底图是独立图层，使用同一地理坐标叠加。修复了模型重试后本地道路底图隐藏却没有恢复的问题；城区信息卡可明确选择“同源道路示意图”或“卫星影像”，离线模式固定使用本地示意图。

原模型统一地面椭球高5m。现在离线时将模型整体下移5m对齐椭球面；在线真实地形启用时，采样城区中心第12级地形高程并调整模型整体高程。采样限时8秒，失败会提示，并保留手动高程偏移。此为城区整体高程适配，不是逐栋贴地，地形起伏较大的位置仍可能存在高差。

没有对整片建筑随意做水平平移。卫星影像中的楼顶倾斜、阴影和不同拍摄年份仍可能与简化三维模型产生差异；切换同源道路示意图适合稳定竞赛演示。
